## 0. The site went down today. Read this before diagnosing anything.

winlew.co became unreachable for hours — **static files and FTP included** —
while the backend behind the tunnel answered in 0.3s throughout. If it happens
again, this is what it was, so nobody burns another afternoon on it:

**Cause.** The 429 handling added this morning honoured the RPC provider's
`Retry-After` header exactly. Alchemy returns `60`. One Solana RPC call could
therefore sleep for up to 180 seconds across its retries, and `/api/profile/me`
and `/api/faucet/status` each make several. Every one of those sleeps happens
inside an HTTP request that is holding a PHP worker on **shared hosting**, where
the account gets a small number of concurrent processes. Enough of them asleep
and the account has none left — at which point the host stops serving everything
for that account, static assets and FTP with it.

**The tell that misled us:** a static favicon failing looks like a host problem,
because on a normal server static content does not depend on PHP workers. On
shared hosting it does — per-account limits gate the lot. The owner spotted the
real correlation first: stop the bot and the website recovers, because ngrok then
502s instantly and the workers are freed.

**Fixed three ways** (`fb999c6`, `4b40dab`, `66e762a`):
- The retry is capped: 2s per attempt, 4s total per call, and it gives up rather
  than sleeping past that budget. Measured 3.9s against a server demanding 60s.
- `api-proxy.php` gained a 5s connect timeout. It had none, so a backend that was
  *down* held a worker for the full 25s.
- `api-proxy.php` gained a **circuit breaker**: three consecutive failures and
  the next 30 seconds are refused in microseconds without opening a socket. It
  fails OPEN on every internal error, so it can never take the API down itself.

**Do not "fix" this by raising the retry budget.** That is the bug.

## 3. What is new

**Account bans.** Wallet bans could never stop a farmer making an eighth wallet.
`src/faucet/userBans.js` is an exact-match list of Discord IDs, checked in
`eligibility.js` before the wallet ban and in quiz redemption.

```
!faucetbanuser <id-or-@mention> [--review] [reason]
!faucetunbanuser <id>
!faucetbanusers
!unregister <wallet>        removes a wallet from the airdrop registry
```

There is deliberately **no cluster walk** for accounts — Discord gives no funding
graph, and linking two accounts by shared IP or device would be a guess dressed
as evidence. A test asserts that file never imports those signals.

`!unregister` exists because a faucet ban did **not** remove a wallet from the
airdrop list, so a banned wallet stayed queued for a distribution.

**App 0.2.0** with local notifications — faucet ready, quiz cycle closing, 48h
idle, then weekly ×4. No Firebase, no push tokens, nothing about a device stored
on a server; all of it is predictable on the phone. Signed with the SAME key as
0.1.0, so it upgrades in place.

**Payout receipts.** `npm run receipts:verify` replays every receipted payout and
exits non-zero on a mismatch. Off unless `GEOPROOF_RECEIPTS_ENABLED=true`.
`@xyo-network` is deliberately NOT a dependency of this repo.

**Site logging** now tags every event `[FAUCET]` / `[QUIZ]` / `[GAMES]` /
`[WALLET]` / `[MERCH]` / `[ROLES]`, logs **refusals** as well as successes, and
gives each line a short trace handle. Routine `cooldown` refusals are dropped on
purpose — they fire whenever anyone taps claim twice and would bury the rest.

## 4. Things that look wrong and are not

- **`[FAUCET]` is quiet.** Cooldown refusals are filtered out by design. Successes
  still post, so total silence while people are claiming means the *logging* is
  broken, not the faucet.
- **A `[WALLET]` line saying "wallet-only session".** That is correct for a
  wallet-only sign-in. It previously printed `User: —` beside "known Discord
  account", which was the log contradicting itself.
- **`[rpc] only one non-public endpoint is configured` at startup.** True and
  unresolved. See §6.
- **`!modhelp` arrives as two messages.** It passed Discord's 2000-char limit;
  chunked rather than shortened, because the admin list only grows.
- **A held payout stays `pending`, never `failed`.** Unchanged from yesterday.
- **The APK does not need reinstalling for web fixes.** It is a Capacitor shell
  loading `https://winlew.co/app/` remotely. Only native changes need a rebuild.

## 5. Two bugs worth knowing about, both already fixed

**A restart could silently un-ban everyone** (`1788fe6`). `bootstrapFile()`
judged local-vs-remote by counting top-level keys, and `wallet_bans.json` is
`{version, bans:{}}` — so an EMPTY ban list looked like content and overwrote a
populated remote. Found with the live list already emptied. If bans ever vanish
again, look here first.

**The app's claim card never refreshed** (`2d178f8`). `loadFaucet()` ran once on
boot and never again; an Android WebView is not reloaded when the app is
foregrounded, so the card showed state from first launch indefinitely.
