# Platform Completeness Audit — July 2026

Date: 2026-07-15
Scope: a full inspection of every reachable page/module/feature on the live WinLEW platform, ahead of starting Version 2.4. Not a new roadmap item — no new features, no placeholders, no redesign. Only genuinely incomplete/inaccurate things on already-shipped pages were fixed; everything else is documented here for a deliberate decision later.

## Method

Every real, reachable HTML entry point under `src/public/` (`/`, `/verify/`, `/verify/profile.html`, `/mole-hub/`, `/quiz/`, `/faucet/`, `/whitepaper/`, `/transparency/`, all `/discord-bots/` pages, the 6 linked `/modules/*.html` pages, `/health/`, `/winlew-forge/`) was loaded with a real headless browser at both 1440px and 390px, checking console errors, unexpected 404s, nav consistency, and horizontal overflow. Every internal link was crawled. The Whitepaper's content was checked against what has actually shipped this session (2.1–2.3). The full `src/public/` tree was grepped for stale copy, `TODO`/`FIXME`/placeholder text, and duplicate wallet-connect implementations.

## Fixed (genuine incomplete implementations / inaccuracies on live pages)

1. **Whitepaper caused real horizontal page-scroll on mobile.** The §5 Ecosystem Architecture table (added this session) had no width constraint, forcing the whole page — not just the table — to scroll sideways at 390px (`scrollWidth` 527px against a 390px viewport). Fixed by wrapping all three whitepaper tables in a `.tableWrap` scroll container (table content stays fully accessible via its own horizontal scroll) plus `overflow-x:hidden` on `html`/`body` as the actual root-scroller safety net (`overflow-x:hidden` on `body` alone doesn't stop `<html>`-level page scroll — confirmed by testing, not assumed). Verified: the page can no longer be scrolled sideways at all, the table content remains fully reachable via internal scroll, zero console errors. A regression test was added to `test/nav/site-nav.e2e.test.mjs` (a `scrollWidth`-based check, now run for every page at every viewport) so this class of bug can't silently ship again.

2. **The Whitepaper described Proof of Value and the Dashboard as unbuilt, though both fully shipped this session.** §2 items 8–9 called the Dashboard "in progress... a known gap, not a finished feature" and Proof of Value "a direction the project is building *toward*... still in active calibration." §11 called the Proof of Value Engine "still in active development." §13's Roadmap table listed Phase 2 as "In build" and Phase 4 as including "dashboards... Coming soon." All of these were factually wrong as of Version 2.2/2.3. Updated the specific passages (in `src/public/whitepaper/index.html`, `docs/whitepaper.md`, and `src/public/whitepaper/whitepaper.md` — kept in sync, as they already were) to describe what's actually live, while keeping the honest "quests/seasonal-ladders/skill-brackets are still genuinely locked" framing intact where it's still true.

3. **The homepage's Proof of Value roadmap card, and the Proof of Value module page, both still showed "WARMING"/"IN BUILD"/46% progress.** Both are live, user-facing status indicators showing false information about a fully-shipped feature — not just stale prose, but an incorrect UI state. Updated both to "LIVE"/100%, using the exact same `statusBadge.online`/`module active` styling the platform already uses for its other shipped modules (Foundation, Games & Trivia) — no new visual pattern introduced. Updated the accompanying feature-list bullets to describe what actually shipped (unified score, Dashboard, milestones, weekly summary) rather than what was originally planned.

4. **`/health/` and `/winlew-forge/` had a stale, incomplete nav pill list.** Both were missing Faucet, Whitepaper, and Transparency — three pills every other real page on the site carries (they simply weren't included in the earlier session-wide nav retrofit). Added the three missing pills to both, matching the exact standard list/order used everywhere else. The `📊 Dashboard` chip was already present and correct on both. **`/health/`'s fix is committed; `/winlew-forge/`'s is not** — that file has the exact same pre-existing, unrelated whole-file whitespace/line-ending diff already sitting in the working tree that `discord-bots/index.html` had in Version 2.2 (confirmed via `git diff`: ~305 lines changed for a 3-line pill addition). Per this project's staging rules, a fix tangled inside a large unrelated pre-existing diff isn't cleanly committable — the working-tree file has the correct nav, but it isn't part of this commit. Flagging this explicitly rather than silently dropping it.

All four fixes were validated together: full test suite 191/191 passing (including the new overflow regression check across every page/viewport), and the nav e2e Playwright suite passing at 390/768/1440px with zero console errors.

## Dead-code cleanup (2026-07-15 follow-up)

Every item below was re-verified independently before any deletion: exact-path grep across `src/`/`test`/`docs` for HTML `href`/`src`, JS imports, CSS `url()`, backend routes in `src/mole/web.js`, test files, and deployment config (`.htaccess`, `netlify.toml`, `package.json`); `git log` for anything whose purpose wasn't obvious from content alone.

**Orphaned duplicate/legacy files under `verify/` and `discord-bots/` — classification: safe to delete. Action: deleted.**
- `src/public/verify/verify.html` and `src/public/verify/terms.html` — confirmed **byte-identical** to each other (a `diff` produced no output). Both are an old "WinLEW Verify" page snapshot (title "WinLEW Verify", a different purple/pink color scheme than the current site), not real Terms of Service content despite the filename — `terms.html` was a misnamed duplicate, not an alternate document. Zero inbound references. Superseded by the current `verify/index.html`.
- `src/public/verify/link-old.js`, `src/public/verify/index-old.html`, `src/public/verify/index-New-OLD.html` — untracked backup snapshots of earlier `verify/link.js`/`verify/index.html` states. Zero inbound references. Superseded by the current live files.
- `src/public/discord-bots/link.js` — a duplicate of `verify/link.js`'s wallet-linking logic under the wrong directory. Zero inbound references.
- All five confirmed via exact-path grep (not substring) across the whole repo before deletion. Same class of leftover the Version 1 Unified Authentication cleanup already removed one instance of (`src/public/link.js`) — these were missed at the time.

**`src/public/discord-bots/bothub.html` — classification: safe to delete (broken + superseded). Action: deleted.**
Zero inbound references. Contains a literal unrendered Python template artifact — the string `class="btn ".strip()` appears four times — and a different color scheme than the rest of the site. Present unchanged since the initial commit (298e0c2); title "WinLEW — Bot Services" suggests an early, abandoned draft of what became the current live `discord-bots/index.html`. An independent, earlier audit (`docs/site-navigation-link-audit.md`, 2026-07-10) had already reached the same conclusion and recommended deleting it — found during this cleanup's own reference-checking, not assumed.

**`src/public/gaming-hub/` — classification: mixed. Action: partially deleted, redirect preserved.**
Git history proves this beyond doubt: commit `9592591` ("Connect Mole Hub wallets through shared hosting") literally **renamed** `gaming-hub/js/games/*.js`, `gaming-hub/css/styles.css`, `gaming-hub/docs/BUILD_ORDER.md`, `gaming-hub/ROADMAP.md`, and other core files to `mole-hub/` (`git show --stat` shows them as `{gaming-hub => mole-hub}` renames) — `mole-hub/` is the direct, git-recorded successor of `gaming-hub/`, not a parallel effort. The one remaining **tracked** file, `gaming-hub/index.html`, is already a correct, minimal redirect stub to `/mole-hub/` (confirmed working — a live crawl showed it successfully lands on the real Mole Hub page) — **left untouched**, along with the sibling flat-file redirect `src/public/gaming-hub.html` and the `.htaccess` server-level rewrite (`gaming-hub(?:\.html)?/?$ → /mole-hub/`), both already correct and unrelated to this cleanup. Deleted: 109 **untracked** leftover files that were never part of the redirect (old `app.js`/`legacy-app.js`/`old-app.js`, `old-index.html`, ~80 historical build/patch-note markdown files for versions long since superseded, and duplicate game-card image assets — including two games, "Mole Market Rush" and "Tunnel Tap," that never shipped and appear nowhere in the current Whitepaper/roadmap). Every deleted file was confirmed untracked (`comm -12` against `git ls-files` showed zero overlap) before removal, and had zero references anywhere in the live site.

**`src/public/wallet/` — classification: must remain — NOT WinLEW code. Action: none.**
This is a separate product's deployed build output, not orphaned WinLEW dead code: `wallet/index.html`'s title is "GeoWallet — The XYO Ecosystem Wallet," and `wallet/netlify.toml` is a dedicated Netlify deploy config for a `@geowallet/web` pnpm-turbo monorepo workspace app, with its own manifest, service worker, and icon set. This is the exact same category as `geoagora/`/`geohackers/` (separate products deployed alongside WinLEW's own site under shared hosting, out of scope for a WinLEW platform audit) — the original survey conflated it with genuine WinLEW dead code by only checking "is it linked from WinLEW's nav," which was the wrong test for a foreign deployment. **Not part of the current live WinLEW platform, and not touched.**

**`src/public/trenchcraft/` — classification: safe to delete (superseded duplicate). Action: deleted.**
Fully untracked, zero git history. `trenchcraft/index.html`'s title is "$WinLEW Forge" — a `diff` against the current live `src/public/winlew-forge/index.html` showed only 21 lines different: missing `nav.css`, the standard nav pill set, and the `📊 Dashboard` chip, plus a stray `/gaming-hub/` link (predating the gaming-hub→mole-hub rename above). This is an earlier, superseded draft of the same live page under an earlier working name, not independent content. Deleted.

**`/modules/quests-progression.html` — classification: live and intentionally retained; content was stale. Action: repaired, not deleted.**
Confirmed reachable (linked from the homepage roadmap and from `core-infrastructure.html`'s CTA chain) — this is a real, live page, not orphaned. Its "LOCKED" status remains accurate for the majority of what it describes (seasonal leagues, skill brackets, access tiers, levels/badges — all still genuinely unbuilt), so the badge was left as LOCKED. Updated only the two ship-list bullets and the intro paragraph that claimed milestones/streaks don't exist at all — they do now, on the Dashboard (2.2/2.3) — to honestly distinguish "basic milestones/streak visibility: live" from "the full quest/reward/seasonal system described here: still locked." No feature-set expansion, no new sections.

**Additional finding, outside the four documented items — a real, broken backend route, found by this cleanup's own required verification step ("confirm it is not served by backend routing").**
`src/mole/web.js` had two routes depending on `src/public/link.js`, which was deleted as dead code in Version 1 (confirmed via `git log`: commit `27b0f23`, the Unified Authentication milestone) — that deletion was correct (zero HTML references existed), but it left `app.get("/link.js", ...)` (an explicit `res.sendFile` for the now-missing file) and `app.get("/link", ...)` (a ~110-line inline-HTML legacy wallet-link page whose only script tag pointed at the now-404ing `/link.js`) silently broken ever since. Verified nothing in the codebase links to either route (exact-path grep) and that the real OAuth flow (`/discord-oauth-callback`) has redirected to `/verify/` this whole time, never to `/link`. Removed the dead `/link.js` file-serving route entirely, and replaced `/link`'s broken inline page with a 302 redirect to `/verify/` (preserving `session`/`app` query params) rather than deleting the route outright, in case an old bookmark or shared link still points there — matching this cleanup's own redirect policy for previously-real, now-superseded entry points.
